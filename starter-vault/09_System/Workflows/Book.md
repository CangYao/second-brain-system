# 书籍整理与增量更新工作流

任务类型：book_update。入口：[[09_System/Workflows/ROUTER]]。

## 契约补充

共享契约：[[09_System/Workflows/CORE-CONTRACT]]。输入为可定位的书籍身份及用户材料／明确研究要求；标题不足以区分作者或版本时先澄清。

Canonical dependencies：[[09_System/Templates/Book-Fiction]] 或 [[09_System/Templates/Book-Nonfiction]] 选一；通常由 Codex 整理，无强制业务 Script。网络补充遵循下文来源规则。

写入与更新：目标为 03_Books/Fiction 或 03_Books/Nonfiction 的唯一书籍；按共享 identity 策略先匹配再增量写回。缺资料时只保存可确认内容并列待补充项，不称已完成完整研究；完成须通过共享判定及本文件专项检查。

## 最小读取范围

读取 AGENTS.md、ROUTER.md、本工作流、目标书籍笔记、明确相关的 Inbox 文件，以及一种对应模板。先定位目标笔记以确认分类，避免同时加载两种模板。

按明确书名或路径定位 03_Books/Fiction 或 03_Books/Nonfiction 中的目标。必要时只查相关已有书籍索引或这两个目录的文件名，不读取其他书籍正文。Inbox 优先使用用户指定文件或目标笔记的来源链接；不能唯一定位时只问一个必要问题。

任务涉及获准晋升时，按共享 identity 规则局部搜索相关 `01_Knowledge` 候选，并按需读取候选正文及现有 Knowledge Template；不扩大为全库扫描。

## 执行流程

1. 根据已有 book_category、用户说明或提供内容判断：
   - Fiction：[[09_System/Templates/Book-Fiction]]。
   - Nonfiction：[[09_System/Templates/Book-Nonfiction]]。
   无依据且分类影响落盘位置时先澄清。
2. 优先读取目标书籍笔记和相关 Inbox 内容。书籍尚无正式笔记且用户要求整理时，按对应模板创建到 03_Books/Fiction/书名.md 或 03_Books/Nonfiction/书名.md。
3. 对照已有章节增量补充；保留原有表达，不重复复制相同内容，不因为模板有章节就编造信息。
4. 新观点保留时间：有实际形成日期则记录该日期，否则标为未知并注明整理日期。观点变化追加当时观点、后来的变化、原因和当前理解，不直接覆盖旧观点。
5. 分开记录作品内容、用户评价与 AI 分析。用户明确偏好按 preference 标注；个人 AI 推测按 inference 记录 confidence、evidence、updated。
6. 来源统一保存在 sources 列表；必要关联写入 relations 列表及正文 Wikilink。
7. 按 [[09_System/Workflows/CORE-CONTRACT#Knowledge Promotion 与跨来源节点]] 判断观点是否值得晋升，不机械拆书。当前任务已授权相关知识整理与落盘时，先局部搜索并匹配：已有对象优先更新，无匹配且独立价值充分才创建到 01_Knowledge；身份歧义停止并报告。仅授权更新 Book Note 时只报告少量有依据的晋升候选，不额外创建文件。
8. 保留已有 id 和 created，实质更新时更新 updated；阅读日期不从笔记创建日期推断。

## 来源与理解的深度传递

写作深度与质量验证统一遵循 [[09_System/Workflows/CORE-CONTRACT#V1.1 Knowledge Quality Contract]]，不在本 Workflow 重复定义。

Book Note 不只是逐章摘要或 bibliographic metadata。对于 STANDARD／DEEP 的非虚构、经典、理论或研究型书籍，按材料与任务需要保存足以理解作品的核心问题、重要论证、关键证据／文本、解释背景、代表性分歧与适用边界；不要求穷尽全书。未取得或未阅读的材料明确标注缺口，不因深度要求虚构内容或扩大读取授权。

在任务已授权从 Book Note 生成 Knowledge Note、Concept Note、Guide 或 Decision material 时，衍生笔记保留理解自身核心主张所需的最小充分证据与上下文。不得仅写“见 Book Note”或“见第 X 章”，将理解责任完全转移给来源笔记；也不重复复制整段书籍内容。Source Note 保存完整背景（以实际取得与阅读范围为限），Derived Note 保存理解自身结论所需的最小充分上下文；其余背景通过链接复用。

Book Note 继续作为来源入口；晋升后的 Knowledge Note 以知识自身为中心，可按共享规则吸收其他来源并保留分歧，不按来源名称自动拆成多个副本。晋升条件与融合判断只在上述中央规则维护。

## 网络资料补充

当用户要求补充、整理或研究一本书，而目标书籍笔记、Inbox 和用户提供的材料不足以回答所需问题时，可主动检索网络公开资料。用户明确要求公开资料、网络信息或网上评价时，即使本地已有笔记，也按请求补充。若书名、作者或作品版本存在歧义，先通过本地资料或一个必要的澄清问题确认目标。按最小范围读取 [[AGENTS]]、[[09_System/Workflows/ROUTER]]、本工作流、目标书籍笔记、必要的 Inbox 内容及对应的一个 Book Template；不扫描整个知识库。

### 检索范围与基础信息

先检索少量高可信来源；结论仍缺依据时，再补充少量优质资料整理和必要的读者讨论。围绕用户要求及缺失信息检索，信息方向包括：

- 官方作品页或正版平台简介、作品状态、字数、章节或卷结构。
- 作者公开信息、出版社信息和官方采访。
- 主角、主要人物、势力、世界观、修炼体系、重要概念和核心设定。
- 作者其他作品之间的关系、作品主题、风格讨论和公开书评。

对长篇小说使用“网络资料骨架 + 用户后续补充”：按需建立基础信息、人物、势力、世界观、修炼体系、主题和风格的简要骨架。不得默认读取整本原文或大量章节；用户以后提供的具体章节、原文或阅读笔记再用于增量补充。检索到足够支持所需结论时停止，不做无目的扩展搜索。

### 来源分层与核对

整理时识别并保留每个主要来源，优先引用可直接支持对应说法的来源：

- **高可信来源**：官方作品页、正版阅读平台、作者本人公开信息、出版社、官方采访。可用于确认基础事实。
- **中可信来源**：长期维护的百科、较完整的资料站、多来源一致的结构化整理。可辅助确认事实；对重要细节尽量用独立来源交叉核对。
- **参考性质来源**：知乎、贴吧、Reddit、论坛、豆瓣长评、书友讨论、评论区、个人博客。只能作为读者观点、社区总结、常见解读或争议意见，不直接写成确定事实。

人物身份、势力关系、修炼体系、世界观设定、剧情顺序、卷章结构和作者创作信息等重要事实，尽量进行多来源核对。多个独立来源一致时标记为“多来源一致信息”。只有单一来源、来源不明或依据模糊的内容标记为“待核实内容”。来源冲突时不自行择一作为定论：记录不同说法及各自来源，标记为“存在争议的说法”或“待核实内容”。不得把来源数量多但彼此转载的材料误称为独立交叉验证。

### 笔记中的信息层级

按内容需要在正式书籍笔记中新增或沿用以下层级；无对应资料时可省略，避免空标题：

- **已确认信息**：由官方或高可信来源支持的基础事实，并保留来源。
- **多来源一致信息**：由多个独立来源相互印证的信息，保留主要来源。
- **读者普遍总结**：多处读者讨论中出现的概括或观点，明确标注为社区总结或读者观点。
- **存在争议的说法**：保留不同来源的具体说法和出处，不强行消解冲突。
- **待核实内容**：只有单一来源、模糊来源、记忆不确定或尚无法确认的信息。
- **AI综合分析**：Codex 基于公开来源作出的归纳或分析，明确标为 AI 分析，不得冒充用户观点或作者明确主旨。

### 用户观点、读者观点与 AI 分析

网络资料与用户个人内容分别记录。用户明确表达“我觉得……”等观点时，作为用户观点，按已有个人内容规则标记其性质；来源中的评论作为“读者观点”或“社区总结”；Codex 的归纳放在“AI综合分析”并说明其依据。不得将读者评价改写成用户偏好，也不得把 AI 推论说成作品事实或用户确定观点。个人 AI 推测仍按 AGENTS.md 记录 confidence、evidence、updated。

### 来源保存、访问失败与隐私

将主要来源 URL 或来源说明保存在正式笔记的 `sources` 列表或相应正文条目中，确保事实和观点可以追溯。只记公开资料，不记录用户名、密码、Cookie、Token、账号信息或其他敏感数据。

网络访问失败时，不虚构资料，保留用户已有内容，并标记“网络资料暂未取得”；可以在后续任务中再次补充。遇到登录墙时，不尝试获取或保存凭据；必要时提示用户自行在 Codex 内置浏览器登录后提供可访问页面。检索完成后，简要报告来源类型、更新部分、待核实内容和明显来源冲突。

## 完成检查

核对 book_category、来源、新增内容依据、旧观点是否保留以及 YAML 合法性。按上述共享质量契约验证实际 Book Note 及本任务已授权生成的衍生笔记。不自动修改模板、AGENTS.md 或其他书籍。按 ROUTER 的统一格式报告。
