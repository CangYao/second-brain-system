# Purpose-aware compression

压缩是按用途控制信息损失，不是减少必要阅读或固定总结成N点。用途可组合；与FAST/STANDARD/DEEP是不同维度。

| Purpose | 保留优先项 | 通常可压缩 |
| --- | --- | --- |
| UNDERSTAND | 问题、概念关系、必要语境、承重证据与推理、边界 | 重复表述与无关细节；不能只剩结论 |
| EXPLAIN | 受众所需词义、推理阶梯、必要例证、易误读处 | 不影响解释的专业枝节；比喻不替代证明 |
| REFERENCE | 定义/关键区别、条件、可检索标题和locator、必要出处 | 修辞引入和重复案例；不压成无法理解的标签 |
| DECIDE | 与选择有关的机制、前提、证据强弱、风险/未决与不适用范围 | 不改变判断的背景；不强行给行动或当成专业结论 |
| COMPARE | 本源定义、语境、理论角色、证据类型、机制/范围/版本 | 无关章节；只准备本源理解，不判断跨来源关系 |
| STUDY | 概念依赖、难点、复述所需证据/例证、误区、再读入口 | 装饰性细节；真实互动与掌握反馈交 ai-reading |

## Compression loop

1. 确定用途和用户篇幅要求；找出不可丢的主张、承重证据、条件、因果链关键步骤、归属、重要分歧与限制。
2. 合并重复、选择足以说明机制的例证，删去对当前问题无增量的横向扩写。承重案例不可因“示例可删”而全删。
3. 压缩后对照实际来源及已核验解释：否定、量词、因果、条件、对象、范围、强度或作者归属是否改变？证据是否仍能解释结论而非只留locator？
4. 有损失时修回必要内容，先减少非承重扩展；仍不能在预算内保真时说明局部/短版限制，不能声称完整深读。用户要求N点可以用N点表达，不把数量当完成标准。

范围与材料足够支持当前问题、承重回查通过、重要缺口已披露时可以总结。局部总结允许，不要求为此读完无关全文。结论依赖关键未读/不可验证材料时停止该结论，并交接缺口。

正文标题应表达知识内容，认知结构不等于heading结构。保留理解需要的证据和解释，不默认生成行动、自测、跨领域案例或更多来源。新增段落不能改善当前理解、验证判断或揭示边界时停止扩写。
